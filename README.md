## 快速开始（坚果云）

1. 坚果云网页 → 账户信息 → 安全选项 → **添加应用密码**（不是登录密码）。开着微信二次验证会返回 403，需先关掉。
2. 打开任意 `.prg` 工程（同步范围默认就是这个文件所在的整个文件夹），按 `Ctrl+Shift+Alt+C`。
3. 弹出**配置表单窗口**（字段标签上会标注当前值）。首次至少填两项：

   - **账号**：坚果云注册邮箱
   - **密码**：应用密码（不是登录密码）

   其余留空 = 保持不变。要固定同步别的目录，填 **本地目录**（如 `E:\005project-graph`）。
4. 点【保存】，看到「配置已保存（webdav）」即成功。
5. 按 `Ctrl+Shift+Alt+S` 执行首次目录同步，完成后会弹出汇总：

        目录同步完成：上传 12，下载 0，冲突保留副本 0，删除 0，未变 0，超限跳过 0

另一台设备：装同一插件、填同样账号密码、**打开同名同路径的工程**，按 `S` 即可拉取。远端路径规则是 `<云端目录>/<本地文件夹名>/<相对路径>`，所以两台机器本地文件夹名需要一致（或用「远端子目录」手动对齐）。

**改用 S3**：在表单的「类型」里填 `s3`，保存；再按一次 `C`，表单会换成 S3 字段。注意 S3 目前只支持单文件模式（把「模式」填 `file`）。

**只同步单个 .prg**：在表单的「模式」里填 `file`。

**想恢复出厂设置**：在 `.sync.json` 里去掉 `#重置=yes` 前面的 `#`，保存后按 `C` 载入。



**关于 Esc**：主程序的弹窗/表单窗口都不支持 Esc 关闭（`Dialog` 未接 `onOpenChange`、`FormWindow` 写死 `closeOnEscape: false`），请点【取消】或【保存】。这是软件侧的行为，已整理成 issue 草稿见 `issue-draft.md`。

**备用输入通道**：表单窗口打不开时，按 `C` 会自动用记事本打开 `<工程名>.sync.json`；改完保存再按一次 `C` 即可载入。若工程目录不可写，会退回弹窗（Shift+Enter 提交）。

**配置字段**：`类型` `账号` `密码` `地址` `云端目录` `模式` `本地目录` `远端子目录` `忽略` `同步删除` `自动同步` `间隔分钟` `AK` `SK` `桶` `前缀` `pathstyle` `重置`。不认识的键会被忽略，写错不会导致整份配置失效。

## 整目录同步的规则

**范围**：本地根目录递归遍历（含子目录），映射到远端 `<云端目录>/<本地文件夹名>/<相对路径>`。

**判定**：三向比较（本地内容 hash / 远端 ETag / 上次同步基线），逐文件决定：

| 情况 | 动作 |
| --- | --- |
| 本地新增 | 上传 |
| 远端新增 | 下载 |
| 只有本地改了 | 上传 |
| 只有远端改了 | 下载 |
| 两端都改了 | **保留本地，远端版本另存为 `xxx.conflict-时间戳.ext`** |
| 本地删除、远端没动 | 开启「同步删除」才删远端，否则保留 |
| 远端删除、本地没动 | 开启「同步删除」才删本地，否则保留 |

**安全默认**：`同步删除` 默认关闭 —— 只增不删，误删风险最低。开启后才会把删除同步到另一端。

**忽略规则**（`忽略`，逗号分隔，支持 `*`）：默认 `node_modules, .git, .svn, .idea, __pycache__, *_backup, .DS_Store, Thumbs.db, desktop.ini, *.sync.json, *.conflict-*`。冲突副本和时间戳备份不会被再次上传。

**上限保护**：`最大文件数`（默认 800）、`最大总量`（默认 300MB）、单文件大小沿用 `maxSizeMB`（默认 480MB，受坚果云 500MB 限制）。超限文件会被跳过并在汇总里报数。

**性能说明**：`readDir` 拿不到文件修改时间，所以每次同步都要读一遍本地文件算 hash 才能判断是否有变化。目录很大时会比较慢——建议把 `*_backup`、图片原始素材之类放进忽略规则。

**坚果云限流**：目录同步按目录逐层发 `PROPFIND`，请求量与目录数成正比。远端目录数超过 300 会主动中止；自动同步默认关闭，开启后间隔下限 5 分钟，冲突时只提示不处理。

## 同步算法

三源元数据：本地 `stageHash`、远端指纹、上次成功同步的基线（存在扩展私有设置里）。

```
本地未变 + 远端未变  → 无需同步
仅本地变            → 上传
仅远端变            → 下载（写盘前先备份本地）
两端都变            → 弹窗让用户选
远端被删            → 询问是否重新上传
首次连接且两端都有  → 弹窗让用户选
```

冲突选项：**用本地覆盖远端** / **用远端覆盖本地** / **两份都保留**（远端另存为 `xxx.conflict-时间戳.prg`）/ 取消。`.prg` 是 ZIP 二进制，不做内容合并。

**不依赖云端修改时间判冲突**——坚果云不支持 `PROPPATCH`，`getlastmodified` 等于上传时间，每次 PUT 都会变。远端指纹优先取 S3 自定义元数据 hash，其次 WebDAV `ETag`，ETag 缺失才退回 `Last-Modified` / 大小。这与 Remotely Save v3「no remote meta data」一致。

## 坚果云适配

| 限制 | 本插件的应对 |
| --- | --- |
| 应用密码、微信二次验证 403 | 配置向导明确提示，403 时给出针对性错误信息 |
| `PROPFIND` 只支持 `Depth: 1` | 仅用 `Depth: 0` 查单文件；默认走 `HEAD` |
| 不支持 `PROPPATCH` | 见上，不靠 mtime 判冲突 |
| 支持 `ETag` | 用 `HEAD` 取 ETag 作为远端指纹 |
| 免费 600 次 / 30 分钟（付费 1500） | 禁止高频轮询、请求预算保护、503 明确提示 |
| 单次列表 750 条 | 不扫描目录，只操作单个工程文件 |
| 单文件 500 MB | 上传前按 `maxSizeMB` 拦截 |
| 中文路径需编码 | 远端路径逐段 `encodeURIComponent` |

## 已知限制（请务必读）

1. **同步范围是当前打开的 `.prg`**，不是整个文件夹。两端工程文件名必须一致，否则会被当成两个文件。
2. 下载后插件会尝试调用 `project.init()` 刷新画布；若无法刷新，会标记 `NEEDS_RESYNC` 并提示重新打开工程，**下次同步会再次询问**，以此避免旧画布被误上传覆盖远端。
3. 本地变更检测基于 `stageHash`（覆盖舞台节点/连线），**只改标签、引用或附件时可能检测不到**，此时请用「强制上传」。
4. `getFileContent()` / `fs.write()` / `uri.with()` / `init()` 属于主程序**未文档化的内部能力**（靠 Comlink 全对象代理访问），软件升级后可能失效。插件对关键路径做了能力探测与降级，但无法保证跨版本兼容。
5. 配置（含应用密码）以明文存在扩展设置中。**务必使用可随时撤销的应用专用密码**，不要用主密码；不要在多用户机器上共用配置。
6. curl 受限模式（网络通道不可用时自动进入）只支持 WebDAV 的显式上传/下载，不做自动冲突判定，也不支持 S3。
7. 未实现端到端加密、多工程批量同步、目录级同步。

## 装机验证（建议先做）

`out/com.workbuddy.webdav-sync-probe-0.0.1.prg` 是阶段 0 自检插件，按 `Ctrl+Shift+Alt+D` 运行，会检查 Comlink 二进制通道、`getFileContent()`、`fs.read()` 以及 WebDAV 的 `PROPFIND/MKCOL/PUT/GET/HEAD/DELETE`，输出 JSON 报告。它只上传一个 16 字节临时文件并立即删除，不改工程、报告不含凭据。详见 `stage0/README.md`。

正式插件已内置运行时探测：若 `prg.fetch` 无法跨线程传二进制，会自动降级到 curl 受限模式并明确提示，因此自检不是强制步骤，但跑一次能更快定位问题。

## 开发与打包

零依赖打包（推荐，不需要 npm 网络，因为扩展是 Web Worker + Blob URL，不能 import 其他模块，源码刻意保持单文件纯 JS 语法）：

```bash
python tools/build.py          # 生成 out/com.workbuddy.webdav-sync-0.5.4.prg
python tools/build_probe.py    # 重新生成阶段 0 自检包
node tests/smoke.mjs           # 29 个模拟场景回归测试
```

`src/extension.ts` 既是正式源码，也可被 `extprg` / tsdown 编译（文件里没有 TS 专有语法）。`package.json` 按 `create-extprg` 规范书写，未来可直接接官方工具链：

```bash
pnpm install && pnpm dev       # 监听 src 并自动安装到本机
pnpm package                   # 产出 {name}-{version}.zip
```
